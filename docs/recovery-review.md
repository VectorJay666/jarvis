# 睡眠与恢复：运行与迁移反馈

检查日期：2026-10-12。基于仓库 main 的 803f6ef，以及用户提供的需求总结和对话示例网站。此次在本地运行、修改和验证，尚未提交、推送或部署。

## 预览

- Web：http://localhost:8081
- 后端：http://127.0.0.1:9301
- 入口：首页「看睡眠」或右上角健康图标 → 健康详情 →「睡眠与恢复」skill。
- 首页输入也可以直接进入睡眠对话。当前默认是有明确标识的交互演示，可切换真实 Agent。
- 演示提供早晨规划、傍晚调整、今晚准备；切换场景会重新开始对应示例。演示和真实会话分别保存在本机，返回和刷新后可以继续。

## 原版运行反馈

1. 首页的留白、黑白颜色和圆角已有良好基础，适合继续沿用。
2. 原版自然输入通过关键词转成固定功能，例如输入「帮我安排今天，中午不能午睡」会得到固定睡眠卡，无法持续保留限制。
3. 原版「连接 Apple Health」会把演示数值标成 healthkit，并未读取真实设备数据；手动填写缺失字段时也可能混入演示值。
4. 原版启动时会尝试排通知；提醒按钮使用几秒后触发的测试逻辑，用户没有确认实际时间。
5. 旧的团队、聘请和会商功能仍留在其他页，与单 Agent 加 skills 的产品方向存在概念差异。本轮聚焦睡眠入口和专门对话。

## 已迁移的交互

沿用认可示例的核心流程：简短回应、当前计划卡、少量便捷回复、随新反馈调整，以及展开依据。没有要求用户一次填写长问卷。

- 健康详情接入专门 skill 入口。
- 早晨讨论任务和工作量，保留不能午睡等限制，再确认运动意愿。
- 傍晚按延期和当前状态调整安排，不根据截止时间推断任务完成。
- 晚上讨论放松、睡眠目标和提醒；演示已知时间不会重复追问。
- 对话历史保留，当前卡片更新，依据说明事实、缺失信息和规划推断。
- 文献可展开查看标题、年份、类型和来源。首批目录 3 项，只核验了摘要和元数据，非完整全文审阅或穷尽检索。
- 演示自由输入未覆盖时明确说明范围，不将预设答复称为模型理解。

## 真实 Agent 接口

新增 GET /v1/recovery/status 和 POST /v1/recovery/talk。后端运行时读取 skills/sleep-recovery/SKILL.md 和共享证据目录 app/src/recovery/evidence.json，携带会话历史、实际健康快照、当地时间和时区调用已配置模型。

输出有结构校验和证据 ID 白名单。只接受模型最终 content，不将内部推理当作对话回复。未配置返回 503，模型失败或无效输出返回 502，界面保留消息并允许重试。

模型只提出提醒请求。用户已明确今天的时间时接口可以返回 HH:mm，App 预填后仍由用户确认；只有取得 Expo 通知 ID 才显示成功，支持取消。通知点击会打开保存的真实会话。未信任客户端提交的成功回执，模型不负责声明工具执行成功。

## Apple 风格反馈

视觉重点放在系统字体、低饱和灰阶、轻分隔线、少量圆角白卡和清楚的主次关系。对话中的内容比装饰更突出，便捷回复和输入固定在底部，窄屏可换行。

后续建议优先统一产品语言：首页、健康页和对话页都围绕「Jarvis + skills」组织；团队、聘请等旧概念需要单独决定是否保留。正式版的早晨／傍晚／晚上应由时间和上下文自然衔接，当前时段标签用于评审三个演示场景。

## 验证结果与边界

- TypeScript 检查通过。
- ESLint：0 errors，14 个旧代码 warnings；Reanimated / Animated 旧组件的少量 React Compiler 规则按文件豁免，普通 hooks 检查仍启用。
- Node 测试：12 项通过，覆盖多轮约束、提醒时间、缺失记录、来源隔离、模型失败、输出结构和推理内容隔离。模型请求使用本地替身验证，没有实际调用线上模型。
- Edge 浏览器：8 组流程检查通过，无浏览器运行错误；覆盖健康入口、多轮调整、文献展开、取消演示提醒、返回重开、刷新、未配置模型和 360px 窄屏。
- Web 生产导出通过，产物位于 app/dist；未发布。
- /health 和 /v1/recovery/status 返回 200；当前真实对话返回明确的未配置 503。

当前没有模型密钥，因此不能验收真实自然语言理解和个性化建议质量。结构校验和 skill 规则也不能证明模型文本完全没有幻觉，接入后仍需多轮实测。

HealthKit 和 Apple Calendar 的原生桥接尚未实现；已有来源显示与日程手动描述回退。通知排程、取消及返回会话的原生代码已接入，但尚未在 iPhone 验证。Web 不发送系统通知。持久化仅在本机，不提供跨设备连续对话。

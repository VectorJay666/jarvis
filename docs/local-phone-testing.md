# 不登录账号的局域网手机测试

当前方案：Windows 电脑运行页面和 Jarvis 后端，iPhone 连接同一个 Wi-Fi，用 Safari 打开页面。无需 Apple 开发者会员、Expo 登录、云服务器或 VPN。它是浏览器测试，可检查界面和真实 AI 聊天；不能替代 iOS 原生包的键盘、通知、触觉和原生效果验收。

## 现在在手机上做

1. 让 iPhone 和这台电脑连接同一个 Wi-Fi，不能用移动数据代替。访客 Wi-Fi 如果隔离设备，也无法互相访问。
2. 打开 Safari，输入完整地址：`http://192.168.1.219:8081`。
3. 首次打开可能需要等待页面编译；然后上滑面板、输入消息、查看 AI 回复。
4. 本地网络权限提示出现时，允许访问。电脑需保持开机、联网，服务需保持运行。

手机上的 `localhost` 指向手机自己，所以不能使用 `http://localhost:8081`。

## 如果打不开

先在同一个手机 Safari 打开 `http://192.168.1.219:9301/health`。

- 能看到 JSON：后端可访问，再检查页面服务与刷新页面。
- 两个地址都无法打开：核对 Wi-Fi、地址是否变化、访客隔离和本地网络权限。本机已有匹配 Node.js 的 Windows 入站允许规则，未更改防火墙、网络类型或路由器设置。
- 页面可以打开但聊天失败：查看具体错误文字。`configured=true` 只证明填写了模型配置，真实回复才证明模型可用。

## 电脑重启后

在当前项目目录打开 PowerShell，运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-local.ps1
```

该命令只为这一次脚本运行设置执行策略，不修改系统执行策略。脚本自动找当前局域网 IPv4，复用已运行的 Jarvis 后端，重启属于本项目的 Expo 服务，把手机访问地址显示出来。换网络后地址可能变化，使用脚本最新显示的地址。日志保存在忽略 Git 的 `review-artifacts/local-*.log`。

## 旧 Mac 是否能使用

先在 Mac 的苹果菜单 → 关于本机查看 macOS 版本和芯片/处理器。

- 只做后端服务器：不用 Xcode，但当前采用的 Node.js 24 官方支持 macOS 13.5 及以后。更旧系统需要另行评估可用运行环境；不要为了未知兼容性直接降级整个项目。
- 编译 iPhone 原生应用：还要安装与 Expo SDK 57 / React Native 0.86 兼容的 Xcode 和 iOS SDK。电脑是否够用，需要看实际 macOS、机器型号和可升级版本。
- Safari 页面测试：先由目前的 Windows 提供服务即可，Mac 不是这个步骤的前提。

未开通付费开发者会员时，可以在兼容的 Mac/Xcode 上使用普通 Apple 账号的 Personal Team 进行个人真机测试；免费签名通常 7 天后过期，需要重新构建安装。TestFlight 仍需开发者会员。

局域网服务互相连接不需要 VPN；模型服务是否需要代理取决于服务器能否实际访问该地址。本机已能调用配置的模型，不应先假定旧 Mac 必须安装代理。

## 验证边界

本机监听和局域网地址请求通过，不代表其他设备一定可穿过工作室的 Wi-Fi 隔离。最终仍需用户在 iPhone Safari 实际打开；当前没有连接那台 Mac，也没有在 Mac 上启动服务。

2026-10-12 本轮实测：以 390×844 手机尺寸的 Chromium 打开 LAN 地址，确认前端实际请求 `http://192.168.1.219:9301/v1/assistant/stream`；模型返回完整回复，没有页面运行错误。该测试使用桌面浏览器，不是 iPhone Safari 或原生测试。
